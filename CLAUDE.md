# Ghost: agent operating manual

Ghost is a voice-first assistant that triages GitHub issues and records decisions on them. It is a personal tool: one operator, running everything on one Linux workstation (ADR 0001). Ghost is the go-live name and the wake word; the original product documents use the working title VoiceTriage.

Before any non-trivial task, read:

1. [docs/architecture.md](docs/architecture.md) for the current design.
2. The ADRs in [docs/adr/](docs/adr/) for the area you are changing. They are short, and they are the rules.
3. [docs/original/](docs/original/) only for background. It assumes LiveKit Cloud and a TypeScript backend; where it disagrees with an ADR, the ADR wins.

## Status

First increment running on the workstation: generic write gate where everything runs unless the operator's permissions block it or ask first (no undo, ADR 0015; ADR 0034), apps connected to Ghost once as the only source of outside tools (ADR 0034; `~/.config/ghost/apps.json`, a catalog from the public app registry, sign-in, API keys and local packages; reads called directly, every other tool a change through the gate; `ghost-mock-github` stands in before a token exists; `docs/apps.md`), voice pipeline with interceptor and processor slots, `ghostd` with transcript wake and the control API on a Unix socket (ADR 0013; `packages/api/openapi.json` is the contract for the TypeScript apps, regenerate with `make api-schema`), and named agents with their own persona, job, voice and memory (ADR 0014, where they are called conversations; `ghost_core.conversations`, rules named `conversations.*` in the permissions, an Agents screen in the desktop app; the one word to show is *agent*, see GLOSSARY.md), the Android app's screens in `apps/mobile` (`make android`, `make android-install`), and the phone transport on the daemon side (ADR 0016; `ghostd.phone`, a signed listener on the `GHOST_PHONE_LISTEN` addresses, WebRTC through Pipecat's SmallWebRTC, `docs/phone-protocol.md`), reachable from anywhere through the operator's own WireGuard network (ADR 0020; no relay, no public listener), and hold (ADR 0021; "hang on, Ghost" keeps the session while the room talks, the name at the start of an utterance resumes it, nothing heard on hold is kept). Departments and agents (ADR 0024; `docs/departments.md`, `docs/skills.md`): a department is a folder under `~/.config/ghost/departments/` (Ghost's is the config folder itself) with its rules in `AGENTS.md`, its title, voice, permissions (block, ask and quiet rules that narrow Ghost's), watches and hooks in `department.json`, skills, docs and a shared memory (`ghost_core.departments`, `ghost_core.department_tools`, the desktop's Departments screen); agents are hired into a department, moved between them and retired (`ghost_core.conversations`); every department reaches every connected app, less what its permissions block (`ConversationRuntime`, `WriteGate.policy_for`); skills are `SKILL.md` folders read nearest first (`ghost_core.skills`); `infra/templates/` ships three department folders to copy; a skill's scripts run only through `ghost-scripts`, an app whose `run` is a change through the gate. Jev experiment scripts in `docs/benchmarks/scripts/jev_*.py`. Layout in [docs/architecture.md](docs/architecture.md#repository-layout). `make help` lists the developer entry points.

## Rules

- **Everything runs unless the operator's permissions say otherwise; the gate records every change** (ADR 0007, ADR 0011, ADR 0034). The model uses the tools it has: an app's read-only tools are called directly, and every other tool, like Ghost's own operations through `change`, goes to the gate in `packages/core`. The gate resolves the level from `[permissions]` in `~/.config/ghost/policy.toml` (`block`, `ask`, `quiet`, `allow` rules over an app, a tool or its arguments; the most careful match wins; `mode` is `open`, `ask` or `read-only` for what no rule names) plus the active department's own rules, and either runs the change now and Ghost says so, or waits for a spoken yes observed in the pipeline's own transcript; at `ask`, the operator's own request that plainly asks for that call is the yes (ADR 0017; the words come from the tool's name and short arguments, never from the app's description). Every level bounds the arguments, records the proposal and the outcome in the audit, and returns what the app answered. There is no undo: to reverse something Ghost asks for the opposite change (ADR 0015); don't add an undo path back. Never let a change reach an app except through the gate, never let a model set a permission, and don't add per-tool declarations or make Ghost ask by default: what is blocked or asked about is the operator's file.
- **Confirmation classification is pluggable.** Jev when a key is configured, the regex allowlist otherwise, negation guard in both (`ghost_core.confirmation`, `ghost_core.jev`). For confirmation, Jev judges the operator's words inside a session only. A watch may also declare a typed Jev question over its parsed fields (#16), whose answer is one of the watch's declared values, with a declared default on failure. Jev is never on the passive audio path and never decides permission.
- **Issue and comment text is untrusted data, and so is anything an app sends**: tool descriptions, read-only hints, results, notices, and the catalog's text. None of it changes a permission or a prompt, and the model is told not to repeat it (a Mobbin tool description once had Ghost read a billing notice aloud). A tool that doesn't say it is read-only is a change.
- **Deterministic first, the model last.** Data from outside (a webhook, an observation, an app's result) passes through deterministic, tested code (verify, parse, constrain, check) before any of it reaches a model, and then only as typed fields. Where a check can't decide, a watch may declare a Jev question, then a model, in that order, each choosing only among values the operator declared. Don't put a model where a parser or a check will do.
- **A webhook is verified, parsed and checked before anything sees it** (ADR 0027). The listener runs in `ghostd` on its own addresses (`GHOST_HOOKS_LISTEN`) and shares no routes with the control API or the phone listener. Each source's declaration ships recorded deliveries, good and bad, as fixtures that `ghostd check` runs. A public listener may take webhooks only: signature first (the body is not read until it passes), then the source's declared parser keeps typed, constrained fields and drops the rest, then the reference is re-read through one of the app's read-only tools (the department's block rules apply) before it is believed. Never hand a webhook's raw body to the model, never parse one with a model, and never let one write, confirm, or change a permission, rule or prompt. The phone path never goes through it (ADR 0020).
- **Idle audio stays on the machine.** In the passive state microphone frames go only to local models: today VAD plus Parakeet looking for a wake phrase (ADR 0010), later the ONNX wake model. Passive transcripts that contain no wake phrase are discarded immediately and are not logged or stored. Nothing is sent anywhere until the wake phrase fires. The one exception is `GHOST_DEBUG_AUDIO=1`, off by default: the operator sets it by hand for a debugging session, and it logs transcripts and audio decisions to the local journal or terminal only (`ghost_voice.debug`). Never turn it on in a committed config or unit file.
- **Outside tools come from apps the operator connects; there are no abilities and no declarations** (ADR 0034, superseding ADR 0022's declarations and ADR 0024's per-department servers). An app is an entry in `~/.config/ghost/apps.json` (`ghost_core.apps`): a URL Ghost signs in to (`ghost_core.signin`, OAuth with tokens in a 0600 file per app) or sends a key to, or a command it runs, secrets as `${NAME}` from the environment (app keys the desktop saves live in `~/.config/ghost/apps.env`, which the vault renderer never rewrites). The desktop connects apps from Ghost's own copy of the public registry (`ghost_core.catalog`, refreshed at most hourly, never queried live on a turn). Every department reaches every connected app. Every tool is offered under the app's name (`github_issue_write`). Never add a capability by editing the daemon or the pipeline, and never write a bespoke client for a service: connect an app ([docs/apps.md](docs/apps.md)). The agents (`conversations`), the departments, the outputs, the skills and Ghost's fixed intents are the only in-tree tool sources (`ghost_core.source.ToolSource`).
- **The product says app, never MCP or server** (ADR 0034). The desktop, the phone, the voice, the prompts, tool descriptions, the waiting list and operator docs say *app*, *connect*, *sign in* and *permission*; catalog titles lose the protocol's name. The code keeps `mcp` only where it names the protocol library.
- **The control API never carries passive audio or passive transcripts, and secrets go in but never come out** (ADR 0013). The model has no route to it. A Confirm click in the operator's own desktop session is confirmation evidence, recorded as `classifier: ui`.
- **Conversations are core** (ADR 0014). `ghost` is conversation zero and every wake lands in it. A conversation's persona, memory and notes are files under `~/.local/share/ghost/conversations/<slug>/` that Ghost writes only through the gate; the transcript and every compaction version are in SQLite. Memory is private per conversation. Persona text shapes the prompt: a thread Ghost creates by voice starts with a short persona Ghost drafts from the conversation (ADR 0019; the operator edits it), but changing a persona by voice stores the operator's words verbatim; never let the model paraphrase those. Session transcripts are stored; passive audio still is not.
- **Debugging audio goes through `ghost_voice.debug.audio()`**, which is silent unless `GHOST_DEBUG_AUDIO=1`. Do not add ad-hoc transcript logging elsewhere.
- **Secrets come from the environment**, loaded from the operator's secrets store when the service starts. Never commit a token, and never put one in a prompt or a log line.
- **Performance is a feature** (ADR 0018, [docs/performance.md](docs/performance.md)). Measure before and after any change made for speed (`make perf`, `make latency`); a change that adds a step to a turn says what it costs; every release runs `make perf` and keeps the report in `docs/benchmarks/perf/`. Speed never overrides the privacy, gate or secrets rules.
- **A department is a folder the operator edits; its permissions only narrow** (ADR 0024, ADR 0034). The model never writes `department.json`, `apps.json`, `policy.toml` or a department's rules except by appending the operator's words verbatim through the gate; a department's `permissions` add `block`, `ask` and `quiet` rules over the operator's and can never `allow`; a department's session reads and writes only its own department's files; a skill never widens anything or runs code outside the gate. Moving an agent moves its folder, memory and transcript; a department's default agent is not moved.
- Python only for the backend and desktop (ADR 0003). Manage dependencies with `uv`; pin versions in `uv.lock`.

## Commits

Conventional commits. Every change reaches `main` through a pull request: `main` takes no direct pushes, and a PR merges only when the `ci` workflow passes (`.github/workflows/ci.yml`: ruff, pytest, `openapi.json` and the TS client current, typecheck, vitest, the desktop build, rustfmt and clippy on the Tauri shell; the ruleset requires its `ci-ok` job) and the branch is up to date with `main`. Run `make lint test` and `pnpm typecheck` before pushing. Don't merge a red PR or ask for a bypass; fix the check.
