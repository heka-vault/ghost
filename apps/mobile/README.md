# Ghost for Android

Expo and React Native, Android only. The screens are rebuilt from the prototype in
`apps/desktop/src/prototypes/mobile/` and follow `docs/design-system.md`; `src/theme/tokens.ts`
copies the desktop tokens, so change both together.

## Run it

| | |
|---|---|
| `make android` | Dev build on the USB-connected phone, with Metro and hot reload. The phone loads its JavaScript from this machine over the USB cable (`adb reverse`). |
| `make android-install` | Standalone APK, JavaScript bundled, installed and launched on the phone. Runs without the workstation. |
| `make android-apk` | The same APK into `dist/android/ghost.apk`, no phone needed. |
| `make mobile-web` | The app in a browser, for layout work without a phone. |

Needs the Android SDK at `~/Android/Sdk` and JDK 17 (override with `ANDROID_HOME` and
`ANDROID_JAVA_HOME`). The phone needs USB debugging on. `android/` is generated by
`expo prebuild` from `app.json` and `package.json` and is not committed; Make regenerates it
when either changes. Builds are arm64 only (`ANDROID_ARCH`). The APK is signed with the
debug key: fine for your own phone, not for the Play Store.

## How it's put together

- `app/`: routes (expo-router). `pair/` first, then the tabs (Home, Activity, Settings)
  and `session`. The session ends back on Home; there is no summary to read while driving.
- `src/desk/`: everything the phone knows about the workstation goes through the `Desk`
  interface in `types.ts`. The phone never uses the control API (ADR 0013). `live.native.ts`
  talks to ghostd's phone listener (ADR 0016, `docs/phone-protocol.md`): signed HTTP for the
  status and the audit log, and a WebRTC call into the voice pipeline for a session. `mock.ts`
  stands in on the web.
- `src/phone/`: the phone's own state (preferences, the last ended session), pairing in
  secure storage, and request signing.
- `src/ui/`: phone primitives (48dp targets, 64dp Start, 80dp End), the voice presence, rows.
- Non-visual helpers shared with desktop (phase text, relative time, audit summaries, the
  ghost drawing) come from `@ghost/ui`.

## Confirming a change

By voice only. When Ghost asks before a change, the session screen shows the question and
“Say yes to go ahead”. The yes travels through the pipeline like any other turn; Jev
classifies it and the gate writes. There is no Confirm button on the phone.

## Pairing with the desk

Same Wi-Fi only for now. On the workstation set `GHOST_PHONE_LISTEN=<LAN IP>:8765` and
restart ghostd; with `ufw` on, allow that TCP port and UDP from the LAN. In the desktop app
choose Pair a phone, then on the phone tap Enter the address and type the address and the
six-digit code. Scanning a QR code isn't built yet; the app doesn't ask for the camera.

Only one session runs at a time. Start is refused while Ghost is in a session at the desk,
and while the phone is in one the desk's wake phrase does nothing. In a phone session the
desk stays quiet: no ducking, no chime. Ghost speaks on the phone's speaker.

## The mock desk

The web build (`make mobile-web`) always uses it, and an Android build does too with
`EXPO_PUBLIC_GHOST_DESK=mock`. `MockDesk` plays Ghost on the phone itself: the link comes up,
Start opens a session, the audit log is seeded. The **Mock** pill at the top opens controls
for what the phone can't do on its own: Ghost asking, saying yes or no, a session at the
desk, losing the desk. Pairing accepts any address and code, except `000000` (wrong code)
and an address starting `10.0.0.` (unreachable).
