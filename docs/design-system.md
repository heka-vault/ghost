# Ghost design system

The contract for the desktop app (`apps/desktop`). Every screen follows it. If something you need is missing, ask the foundation owner for a new token or primitive; don't invent one locally.

Live reference: run the dev server and open `/?mock=passive#/gallery`. It shows every primitive in every state, in both themes side by side, and links every route in every mock scenario.

## Principles

1. **Voice first, app second.** Speaking to Ghost is the product. The app shows state, asks for the operator's okay, and lets them configure things. It should never feel like the main event.
2. **One focal point per screen.** Each page has one thing the eye lands on first: the live transcript, the waiting change, the list being edited. Everything else steps back.
3. **Quiet surfaces, one accent.** Neutral grays do the structure. The iris accent (`--accent`) marks the single primary action and the current selection, and nothing else. Semantic colors (ok, warn, danger, info) only mean what they say.
4. **Hairlines, not boxes.** Group with space first, then with one hairline container (`Card`). Never nest bordered boxes inside bordered boxes.
5. **Show state honestly.** Loading, empty, offline, error and in-progress states are designed, not left over. The status dot moves only when something is actually happening.
6. **Plain words.** Sentence case, the operator's own vocabulary, no jargon in primary labels. Technical names (`GHOST_WAKE_PHRASES`, `github_heka.close`) appear only as secondary monospace detail.
7. **Both themes are first-class.** Dark and light follow `prefers-color-scheme`. Check every screen in both.

## Tokens

All values live in `src/ui/tokens.css`. Use the variables; never write a raw hex value, pixel size outside the scale, duration or shadow in a screen.

Every color is written once as `light-dark(LIGHT, DARK)` on `:root`, which has `color-scheme: light dark`, so the theme follows `prefers-color-scheme` with no duplicated blocks. `data-theme="light"` or `"dark"` on any element forces that subtree (the gallery shows both side by side this way). To add a color token, add one `light-dark()` line. `light-dark()` needs WebKitGTK 2.44 or later (Ubuntu 26.04 ships newer) and Chrome 123 or later.

### Space

A 4px grid: `--space-1` 4, `-2` 8, `-3` 12, `-4` 16, `-5` 20, `-6` 24, `-8` 32, `-10` 40, `-12` 48, `-16` 64, `-20` 80. Half steps `--space-0_5` (2), `--space-1_5` (6) and `--space-2_5` (10) exist for control internals only.

Rhythm: 8 between a label and its control, 16 between fields, 24 between groups inside a card, 40 between page sections (`Section + Section` does this), 32 below the page header.

### Size, radius, elevation, motion, layers

- Controls: `--control-xs` 24 (inline dismiss buttons), `--control-sm` 28, `--control-md` 32 (default), `--control-lg` 40. Icons: `--icon-xs` 12 (badges), `--icon-sm` 14, `--icon-md` 16 (default), `--icon-lg` 20.
- Shell: `--rail-width` 76 (the desk's rail), `--window-min` 560 (the narrowest window the shell lays out for, beside other work), `--timeline-gutter` 72 and `--timeline-mark` 10 (the timeline), `--sidebar-width` 244 (kept for the prototypes' frames only), `--settings-nav-width` 216 (the settings area's own nav), `--nav-item-height` 28 (Linear density), `--nav-item-height-2line` 40 (line rows with a status line), `--count-size` 18 (count pills, small badges, key caps), `--panel-inset` 8 (gap around the page panel), `--field-control-width` 320 (the control column of inline fields), `--save-bar-min` 480 (the SaveBar’s narrowest width), `--stop-pitch` 104 (one column per autonomy level in a row of stops), `--touch-target` 56 (the phone’s primary buttons).
- `--page-sticky-top`: set by the shell on `#main`, the bottom of the sticky stack (connection banners plus the compact page bar) from the top of the panel, kept current as banners come and go. Anything a screen pins under the bar (`position: sticky`, `scroll-margin-top`) uses `var(--page-sticky-top, var(--page-bar-height))`; never measure `.g-page-bar` yourself.
- Opacity: `--opacity-disabled` 0.45, the one step every disabled control dims to (filled buttons go neutral instead).
- Radius: `--radius-xs` 4 (kbd, skeleton), `-sm` 6 (small controls, nav items), `-md` 8 (controls, notices), `-lg` 12 (cards, the page panel), `-xl` 16 (dialogs, bubbles, composer), `-full` (pills, dots).
- Elevation: dark mode leans on surface steps and borders; shadows are for things that float. `--shadow-xs` (buttons), `-sm` (the page panel, the selected segment), `-md` (toasts, tooltips, the composer), `-lg` (dialogs).
- Motion: `--duration-instant` 80, `-fast` 120 (hover, press), `-base` 180 (toggles, dialogs), `-slow` 280 (toasts), `-slower` 420, `--duration-posture` 560 (desk to room and back, the one long move in the app). Easings `--ease-out` (default), `--ease-in-out` (loops), `--ease-emphasized` (things arriving). `prefers-reduced-motion` zeroes every duration and stops every loop except spinners.
- Layers: `--z-sticky` 10, `-sidebar` 20, `-banner` 30, `-popover` 40, `-dialog` 50, `-toast` 60, `-tooltip` 70.
- Page widths: `--page-narrow` 680 (forms, settings), `--page-default` 880, `--page-wide` 1160 (tables, two panes).

### Focus

One treatment, applied in `base.css` to every `:focus-visible`: `outline: var(--focus-outline)` (2px solid `--focus-ring-color`) with `outline-offset: var(--focus-offset)` (2px). The offset is transparent, so it reads the same on the sidebar, the canvas and inside cards; the outline follows `border-radius` and survives forced-colors mode. Mouse clicks never show it.

- Text fields, selects and textareas: the border turns `--focus-ring-color` and `--focus-field` adds a 1px ring plus a soft halo (invalid: `--focus-field-danger`). Fields show it on any focus, mouse or keyboard.
- Inside lists, tables, segmented controls and menus, where an outside ring would be clipped: `box-shadow: var(--focus-ring-inset)`.
- A scroller that holds focusable items needs 4px of padding on every side (offset plus ring), or the ring is clipped.
- Buttons in a row sit at least 12px apart (`--space-3`) wherever a focused button can sit next to a filled one: dialog footers, page header actions, card footers. At 8px the 4px ring crowds its neighbour.
- Never remove a focus style without replacing it, and never style focus with a tint alone: the indicator must reach 3:1 (see the table above).

Shared state comes from `useGhost()` in `@ghost/ui` (status, connected, turns, heldTurns, pending, activity, logs, lastEvent, conversationsVersion, client). `activity` is what the live session did, by name and never in words (ADR 0055): the operator's turn opening and closing, tool calls and their results, a handover, a cut, an error; empty outside a session. `turns` holds back the operator's spoken pieces until the turn closes (the status leaves listening, or a reply, note or typed turn arrives), so a sentence said with a pause never appears in fragments while they talk; the screen shows Ghost listening instead, and the words appear once, whole. `heldTurns` counts what is held, for a screen that re-reads the stored transcript (`withoutHeld`). ## Page layout

- **The rail** (`src/app/Rail.tsx`, `rail.css`, `--rail-width` 76) is the desk's one way around, on the window ground: Ghost at the top, then Today, Watching and Apps, each an icon over its 11px label; then the agents themselves (ADR 0061): + to hire one, then each agent's mark (`LineGlyph` lg) over its name, its live state on the mark (a ring in the voice phase's colour while it is in the session, a `--kind-run` pulse while it runs, an accent count while it waits on the operator), ordered by `railAgents()` (in the session, waiting on you, at work, then by when it last worked); choosing one opens the conversation with it (`#/agents/:slug`). The list scrolls inside the nav with a fade at its foot; under 760px of height the names go and the marks stay. At the foot Hearing and Settings, then the room button (Ctrl+.) and the microphone switch, and in development the flask (the Mock badge: the scenario and the prototypes, `DevMenu`). Exactly one current row (`aria-current="page"`, the `--bg-nav-selected` tile, its icon in `--accent-text`); a page of Settings lights Settings, Apps lights Apps. Today carries the count of what needs a decision or an answer (an accent pill on the icon's corner); Agents a pulsing `--kind-run` dot while any agent runs. Every row's accessible name includes its count (“Today, 2 need you”).
- **Ghost's presence** heads the rail: Wisp (`Mascot`, 36) in the phase's pose inside a ring of the phase's colour that breathes while Ghost is live, its state in one word under it (Ready, Listening, Working, Speaking, Starting, Not running, Not listening) and the rest in its tooltip (who it is with, the build). It is the way to the conversation (`#/session`). Not listening (ADR 0057) turns the ring and the word `--danger`: a smart speaker's mic-off light. `moodOf(phase, off)` is the one mapping from phase to Wisp's pose; the gallery shows each.
- The microphone switch (ADR 0057, `src/app/ListeningSwitch.tsx`) sits at the rail's foot. Listening, it is the mic glyph and opens a menu of how long (30 minutes, an hour, until turned back on); not listening, it is the struck mic in `--danger` and one click turns it on. Ctrl+Shift+M does either. The same switch is a row of Settings › Sound and an item of the tray, whose icon is struck through in red.
- The shell owns the rail and the inset page panel. **The panel is the scroller, not the window**: its inset, border and radius never move (Linear). `position: sticky` inside a screen sticks to the panel. Screens never set `position: fixed`, global backgrounds or `100vh` heights, and never call `window.scrollTo`. To scroll programmatically use `scrollIntoPanel(el, { block })` from `src/ui` or `document.getElementById("main").scrollTo()`, not `element.scrollIntoView()`: Chrome moves its Tab starting point to whatever scrollIntoView reveals, so the next Tab skips “Skip to content” and the sidebar. scrollIntoView is fine only in response to a click that should also move Tab order (a table of contents).
- Anything that must stay in reach while the page scrolls (a composer, a save bar) goes in `Page`’s `dock`, never in a homemade sticky footer.
- **The top edge.** Content never cuts hard at the panel’s rounded top. Every `Page` with a header that isn’t `full` gets a compact sticky bar for free (`stickyHeader`, on by default): as soon as the panel scrolls, a 48px strip of opaque `--bg-canvas` (scrolled content never shows through, not even a large title on a contrasting surface) sits at the top of the panel; once the big header has gone under it, the bar shows the header’s `leading` glyph at 20px, the title (14px semibold), the page’s `status` right after it, and the header’s `actions` at size `sm`, over a `--border-subtle` hairline. It sits under any connection banner. `full` and `bare` pages, and `stickyHeader={false}`, get a 24px fade at the top edge instead. Screens never build their own sticky header; the gallery shows the bar under Surfaces, and `--scroll 400` shows it live. **Header actions exist exactly once.** `Page` renders them into one host element and moves that element between the header and the bar; nothing remounts, so a Menu, a `useConfirm` button or an open dialog survives the move, ids stay unique, and keyboard and screen-reader users meet each action once. The scrolled-away header keeps the space so nothing reflows. Put anything you like in `actions`.
- Every screen's root is `<Page>`. Pick the narrowest width that fits: forms and settings `narrow`, single lists and policy `default`, tables, two-pane layouts and the session transcript `wide`, bare canvases `full`. All of them start at the same left edge (41px into the panel at 1440 and 1280), so the title holds still as you move between routes (Linear, Apple System Settings). Inside `wide`, keep reading measures in check yourself: the session's record keeps its words to `--page-narrow`, lined up with the composer under it.
- Shell banners (reconnecting, models loading, not set up) share the page column’s edges: their text starts on the title’s left edge at every width.
- Header: title (what this is), one or two plain sentences (what it's for), actions on the right with the primary action last. 32px below the header to the content.
- Content: group with `Section`s 40px apart; one `Card` per group; rows inside cards. Two-pane layouts put the list left (260 to 320px, sticky) and the detail right.
- The window is at least 1280x800; design at 1440x900. Nothing may scroll horizontally at 1280.

## Copy

- Sentence case everywhere: titles, buttons, labels, badges. “What Ghost may do”, not “What Ghost May Do”.
- Use a real ellipsis, … (U+2026), never three periods, in copy, placeholders and labels: “Connecting…”, “Search issues…”, “Replace…”. The gallery’s typography check flags `...` in text and in `placeholder`, `aria-label` and `title`.
- Typographer’s quotes and apostrophes in every UI string: “Hey Ghost”, “never mind”, “can’t”. Never straight `"` or `'` in visible text. Use `quoted("…")` when quoting what the operator says. The gallery asserts this on every load for its own copy (outside code, mono and `[data-user-content]`); mark nodes that render operator or issue text with `data-user-content` so the same check can run on your screen.
- US English, for an operator in Detroit: color, labeled, center, behavior, summarize, canceled in prose (the API’s `cancelled` status stays as the API spells it, shown in mono).
- Shortcuts read Ctrl, Alt, Shift and Super, never ⌘: write them with `Kbd shortcut="mod+z"` or `formatShortcut()`.
- Say “Ghost”, not “ghostd”, in primary copy: “Restart Ghost to use the new microphone.”, with `systemctl --user restart ghostd` as monospace detail underneath.
- The operator's words. "Ask me first", "Do it and tell me", "Do it quietly", "Not allowed" for autonomy (use `autonomyLabel()` from `@ghost/ui`). "Line" for a conversation in speech ("the Accounting line"), "Conversations" for the screen.
- Name things by what they are to the operator, not to the code: "GitHub token", with `GITHUB_TOKEN` as `detail`. Operation names (`github_heka.close`) appear in mono as secondary detail.
- Buttons are verbs. Confirm labels repeat the action and name the object.
- Notice and toast titles never end with a period (“Saved”, “Couldn’t save”); the body is a sentence and does.
- After a save, one toast everywhere: title “Saved”, body says when it takes effect (“Ghost uses the new levels from its next change.”, “Live now: wake phrases.”), `Undo` where possible. “Applied” is implied by any save that needs no restart. The `SaveBar` restart variant is the only exception: it toasts nothing, the bar says what is left to do.
- One fact, one wording: the nav label and the page title match (“What Ghost may do”), and a line never used reads “Not used yet” everywhere.
- Errors: what happened, then what to do. “Ghost didn’t start. Run `systemctl --user status ghostd` to see why.” Never blame the operator, never show a stack trace as the message.
- Empty states: what will be here and how it gets here. “When Ghost changes something, or asks to, it shows up here.” Don’t promise what can’t happen yet: while models load, say so instead of “Say Hey Ghost”.
- After a middle dot, lowercase: “Live · listening”, “Live · reconnecting”, “Kokoro cached · speech-to-text parakeet”. The part before the dot is the label and keeps its capital; what follows reads as the rest of the sentence.
- Contractions are fine (“isn’t”, “can’t”). No exclamation marks. No “please”, no “successfully”.
- Passwords are write-only (ADR 0036): the UI says “Set” or “Not set” and offers “Replace…”. Never echo, mask-preview or log a value. *Password* is the word for every API key, token and account password Ghost holds; a row is titled by what it is for (“Anthropic”, “Mobbin”), the name (`ANTHROPIC_AUTH_TOKEN`) as mono detail.

## Motion

Motion explains a change; it never decorates. `VoicePresence`, `VoiceWave` (while Ghost speaks) and `StatusDot` are the only things that loop for the voice state. The one character motion is the mascot's: it plays when you reach for it (hover on desktop, a tap on the phone) and settles back to rest, and it loops only where it is the voice state's hero (the phone's 320 presence acts out each phase, which is real ongoing work, and blinks on the Start control). Hover and press 120ms, toggles and dialogs 180ms, toasts 280ms, all `--ease-out` or `--ease-emphasized`. Loops are reserved for real ongoing work: the starting, listening, thinking and speaking dots, spinners, skeleton shimmer, indeterminate progress. With reduced motion every loop stops except spinners (slowed) and indeterminate progress, which stops traveling and instead pulses the full-width bar slowly in place (never a static partial bar that reads as “35% done”); transitions are instant.

| First load | `Skeleton`s shaped like the content. The shell shows a skeleton page while a lazy screen loads and during the first connection attempt. A `chrome: "bare"` route (tray, phone) gets a centered bare placeholder instead, never the desktop page’s shape, and renders itself during the first attempt with `connection="connecting"` from `useLive()`, so its own Connecting layout is what the phone shows. |
| Empty | `EmptyState` inside the card or page where the content would be (`?mock=empty`). |
| Loading an action | The button's `loading`; keep the rest of the page usable. |
| Result | `Notice` (persistent, inline) or `useToast` (transient, with Undo after a save where possible). |
| Error | `Notice tone="danger"` near what failed, with `errorText(e)`. A screen that throws is caught by its route's error boundary; the rest of the app keeps working. |
| Connecting | The first attempt, before the shell decides (about 900ms). The rail’s presence says “Connecting…” / “Looking for Ghost” with a still, neutral dot, and the page shows its skeleton. It never says “Not running” until the Offline page appears, at the same moment. See it with `?mock=passive&connect=600` (shoot with `--wait 300`); `&connect=1500` shows Connecting, then Offline at 900ms, then the screen once it connects. |
| Daemon not running | Handled by the shell for every route with `needsDaemon: true`: the "Ghost isn't running" page with a Start button in Tauri or the systemctl command in a browser (`?mock=disconnected`). Screens don't need their own. |
| Reconnecting | The shell shows a warn banner over the last known screen; the rail’s presence says “Reconnecting · Trying again now” and keeps its lines. Screens keep rendering their stale data (don’t clear it); the sidebar card says “Reconnecting” (still amber dot, never “Not running”); and screens disable every write while `useLive().online` is false: Sleep, Confirm and Cancel (`PendingChange disabled`), Save, the composer (`?mock=reconnecting`, or `&drop=<ms>` on any scenario). |
| Models loading | The shell shows a banner with indeterminate progress. Screens disable voice-dependent actions using `status.models_ready` (`?mock=starting`). |
| Not set up | The model connection is missing something: a password, a sign-in, an address (`GET /model`, whose `ready` is false; it reports the password only as set or not set). The shell shows a neutral banner in the same slot, after models loading: “Ghost needs a model password before it can answer.” with a small secondary “Finish setup” button to Settings › General, where the setup list leads (to `#/welcome` while the mock is active). Not shown on the settings screen’s pages (General, Model, Passwords, Sound, Phone) or Welcome. Re-checked on every route change and window focus (`?mock=firstrun`). Read it with `useLive().setupNeeded`. A screen whose focal point would promise something that can’t happen yet says so itself and calls `useSetupPromptHere(true)`, which hides the banner there (one signal per place): the session’s start state reads “Finish setup to talk to Ghost” / “Ghost needs a model password before it can answer.” with a primary “Finish setup” button (`setupHref`), and Wake drops to secondary. |
| Waiting for okay | `pending` from `useGhost()`, always rendered with `PendingChange`; never build your own card or countdown. The session puts it in the `Page` dock directly above the composer, so it can never sit under the compact bar while its Confirm stays visible (Higgsfield’s approval card above its composer). The sidebar shows it on the live agent’s row: “Waiting on your okay” in `--warn` with an amber dot. One signal per place; no extra badge on the status card. The Confirm button is real confirmation evidence (ADR 0013): it must call `client.confirm()` and nothing else. `PendingChange` counts down from `pending.expires_at`, never `expires_in_secs` (a snapshot). |
| A question | An item whose `question` is set and whose `kind` is `question` (ADR 0051): the row says who asked (“Asked by Ledger”; “Asked by Claude Code, an outside tool”; “Asked by Ledger in a scheduled run” when the answer starts one more run) and when it expires, and under it, aligned with the title, the choices as `secondary` `Button`s, an `Input` with Send for the operator’s own words unless `choices_only`, and a `ghost` Decline. The question and its choices are the asker’s words: plain text, never markup, never a heading. A change waiting for a yes keeps its Confirm and Cancel. |
| Where an item came from | On What needs you, a row’s first meta line names its source in words (`sourceLabel`): “Watch ci”, “Webhook jobs”, “A change”, “Agent Ledger”, “From Claude Code, an outside tool” (icon `PlugZap`, as Outside tools), “Ledger’s scheduled run” or “Ledger’s run for a watch” (icon `CalendarClock`, as a schedule). Never a raw `client:` or `agent:` source. |
| Okay expired | The change lapses: `PendingChange` shows “Expired · Ghost left it alone” with both buttons off for the moment until `pending` becomes null, the audit row turns `expired`, and Ghost says it left it alone (`?mock=expiring`, 8 seconds after load). |

## The two postures

One app, two ways to hold it (the owner's decision, 2026-11-12: the briefing at the desk, the room whenever a voice session is live or the operator has stepped away). The rule is `postureOf()` in `src/app/posture.ts`, fed by `PostureProvider` (`src/app/PostureContext.tsx`), and nowhere else:

| Posture | When | What the window is |
|---|---|---|
| Desk | The operator is using the window (a key, a pointer move of 4px or more, a scroll, a touch within the thresholds below), or holds the desk | The rail and the page. |
| Room, in a session | A live session whose audio is at this desk (not the phone's), and 20 s (`SESSION_IDLE_MS`, the conversation screen's own room-view threshold) without input | On the conversation screen: the rail steps out (`grid-template-columns` to 0, the panel's inset and radius to none) and the conversation screen's room view fills the window. Anywhere else: the room below, with the reply being said. |
| Room, stepped away | No session, and 3 minutes without input (Settings › General: 1, 3 or 10 minutes, or never) | The room (`src/app/Room.tsx`) over the desk. |
| Floating (ADR 0059, opt-in) | A live session at this desk, the floating room on and able to show (its platform, no screen capture), and this window not the one in use (not focused, or not on screen). A held room wins | The window stays at the desk; the session comes forward over the desktop (The floating room, below). |
| Room, held | Ctrl+. anywhere, the rail's room button, Settings › General's “Show the room” | The room, until Escape, Ctrl+. again or “Back to the desk”, which takes focus so Enter leaves. Input doesn't end a held room. A session ending lets a held room go back to the rule. |

- **Overrides**: Ctrl+. holds or releases the room; Settings › General sets the stepped-away delay and whether a spoken session goes to the room; `?posture=room|desk` forces one for screenshots. The choices are this window's (`localStorage`, read in try/catch): how this screen behaves on this desk, not Ghost's setting.
- **The room is laid over the desk, never instead of it.** The desk stays mounted underneath, `inert` and `aria-hidden`, so a draft, a dialog or a scroll position survives a trip to the room. `<html data-posture>` says which posture is showing.
- **The transition** is one move: the desk eases back (scale 0.97, blur, 35% opacity) as the room rises 16px into place, 560ms on `--ease-emphasized`; leaving reverses it. On the conversation screen the rail slides out and the panel's frame opens. Reduced motion: a cut, no blur.
- **The room** is legible from three metres: the clock at 32px, the state word at `--text-6xl`, the things that need the operator at 24-32px (at most three, decide first, then answer, then know, with “N more on Today”), the agents at work with live clocks and the day's counts at 16px. Wisp at 200px in the phase's pose over a slow glow of the phase's colour. Everything on it is a true number from today's records. A narrow window stacks it; a short one drops Wisp.
- **One switch**: the conversation screen's room view is the room posture on that screen (`usePosture()`); the stage's room button holds or releases it like Ctrl+. and the rail's button. The screen keeps no timer of its own.

## The floating room

The room without a window (ADR 0059, `src/floating/`, `floating.html`, a second process of the app on X11 or XWayland; `docs/floating-room.md`). What it shows is `sceneOf()` (`src/floating/scene.ts`) of the posture rule and the daemon's events: `line` at rest (a 56×2px light at the bottom centre, a struck `--flt-red` mic when not listening), `hidden` while the screen is captured (nothing, not even the line), `hold` (the line with "On hold · say “Ghost” to pick up"), and forward: `you`, `listening`, `thinking`, `speaking`, `okay` (a change waits for a yes), `question`, `ending`.

- **Layers**, back to front: the field (one WebGL2 pass at 0.4 resolution: the dim, haze, the glow, a ring of ticks, the scan of the arrival, beams to the apps in use), Wisp (176px, the brand's engine, capped at the scene's frame rate), the words (DOM).
- **Type**: the reply at 800, `clamp(36px, 4.4vw, 96px)`, said words bright with a glow and a hair of chromatic split, the clause being said underlined 3px in cyan (`saying`), the rest at 50% ink. The operator's words once their turn closes: 300 weight and grey as the line while Ghost works, small above the reply after. A question and its answers: 800 type, answers as one-word buttons (Yes in amber, the rest outlined). The label over Wisp: mono uppercase, tracked.
- **The margin** (the signal concept's telemetry, true data only): the agent and the session's clock, calls, open calls, apps reached, the waiting count, the last eight calls (`HH:MM:SS app.tool 1.2 s`, an open call in the phase colour), and Open in Ghost.
- **Hits**: only the answer buttons and Open in Ghost take a click (`data-hit`, the X input shape). Nothing takes the keyboard.
- **Legibility over a light desktop**: a local scrim under the words (radial, 82% black at its centre) and a dark hairline under the line; the dim is 50–60% black.
- **Motion**: the arrival 950ms (zoom from depth, scan, shockwave), the leaving 750ms (Wisp falls back, the light drops to the line), both on the frame clock. 30 frames a second, 60 for the arrival. Reduced motion: one frame per change, no zoom or scan. Forced colours: the glows go, the scrims are `Canvas`.
- **Its own palette**, the one departure from the tokens, local to `floating.css` (`--flt-*`): glow on black and weight 800. The phase hues are the system's pushed to neon: green listening, violet working and questions, cyan speaking, amber only for "waiting for your yes", red only for the mic off.

## Today

`#/`, `src/screens/today`: the desk's home. The page has no visible title (its `h1` is “Today”, visually hidden); the headline is the day in one sentence with real counts, lead in `--text-1` semibold, the rest in `--text-3` regular, at `--text-4xl` (`headline()`: “2 things need you. Ghost made 8 changes, ran 7 jobs and caught 2 things on watch today.”). Above it the day and the way to move through days (‹ ›, `[` and `]`, `t` for today; 30 days back). Under it **the telemetry** (`Signal.tsx`, ADR 0060, the signal concept), only once there is something true to say: no tiles, one hairline, then six figures in large tabular type with a mono label under each (items read, bytes read as the apps sent them, apps reached of those connected, changes made, working now with a live dot, the first word from the last model check; apps and first word link to their settings), and beside them a fine mono margin of the latest calls (time, agent, `app.tool`, items, size, ms; the newest tinted `--kind-run` for four seconds, a change underlined in `--kind-change`, a failure's count in `--danger`) with how many came back in the last minute. The figures are `GET /reach` for the day with each `reach` event folded in as it arrives (`telemetry.ts`: `tallyOf`, `wireOf`), redrawn at most four times a second; nothing is estimated. Under 1180px the margin goes under the figures; under 720px the figures are three across at 20px and the margin shows three calls. Then the timeline, with Now at its head. The talk bar is the dock: Ghost's presence, its state, a field that sends a typed turn and opens the conversation, and Talk (wake), or “Open the conversation” in a session.

Now holds what needs the operator, by what they do about it (`needsOf()`): **Decide** (a change waiting for a yes: the one `PendingChange` card with its clock, Confirm calling the gate’s confirm by id, `confirmProposal`, and nothing else; Cancel; where it came from and Open under it), **Answer** (an agent's or a tool's question: its choices, the operator's own words unless the choices only, Decline), **Know** (one list: Got it, Later, Open), then **Working now** (each run a lane with light moving through it, its live clock in `--kind-run`, what it has read so far, the app and tool it is on now in mono, and the apps it has touched, from its `run-<id>` reach; Stop). Every action of the retired What needs you screen is here; `#/waiting` redirects.

## The timeline

The spine of the app (`screens/today/Timeline.tsx`, `model.ts`). One 2px line down the page from Now to midnight; every row is three grid columns (the time in a 72px gutter, the spine with the moment's mark, the words) all placed in one grid row, so the line runs unbroken under the marks. Marks: a change is a filled dot (`--kind-change`; failed `--kind-failed`; one the operator declined or that expired is a hollow ring), a run a ring in `--kind-run` (filled and pulsing while it runs), something a watch or webhook found a diamond in `--kind-watch`, a question a hollow square in `--kind-question` and its answer a filled one, a note from an outside tool or an app a small dot. Now is a larger accent dot with a slow ripple.

- **What is on it** (`momentsOf()`): every change from the audit but the one still waiting (that is in Decide), every run (`GET /runs`) with how long it took, its calls and its answer (“[SILENT]” reads “Nothing to report”; an unchanged check “didn’t need the model”), everything a watch or webhook found, the questions asked and answered, and what outside tools and apps said. A run's delivered answer is the run itself, not a second row.
- **Clusters**: three or more changes by one agent each within 20 minutes of the next fold into one row (“Legal made 3 changes”), opened to each (`cluster()`).
- **Hours**: an hour label where the hour changes; empty hours fold into one dotted “quiet · 3 hours” gap (`byHour()`).
- **Each row** is a sentence: the agent's glyph and name, a verb in `--text-3` (ran, couldn’t finish, is running, left alone, asked), the words in `--text-2`, a meta part right-aligned (why a run started, how long, its calls). A run shows the first line of its answer under it; Enter opens the whole answer, a cluster's members, the operation in mono and Open.
- **Moving through it**: one Tab stop (roving), ↑/↓ or j/k, Home/End, Enter or Space to open; the filter (All, Changes, Runs, Found, Questions) and the agent select; the day's map on the right (24 hours, a bar per hour as long as it was busy, red where something failed, the hour at the top of the panel lit; a click jumps there), hidden under 1100px.
- **Empty and long**: an empty day says what will land here; a day is read by its range (`since`/`until` on the audit and the runs, ADR 0060), and a day past 2,000 changes shows its newest and says so.
- **Live**: the provider reloads on the `run` event (a run started or ended) instead of polling; only a daemon from before ADR 0060 (no reach) is looked at again once a minute while a run goes.

Amber (`--warn`) means only “waiting for your okay”. Watching's problems (schedules that can't run, broken files in Ghost's folder) are one `danger` Notice at the top of the page; a schedule's failed last run reads “Last run didn’t finish: the model was overloaded.” (`runErrorWords`), the daemon's own message as its tooltip. ## The conversation screen

The session (`#/`, `screens/session`) is voice first: someone speaks to Ghost across a room and glances at the screen. It is not a chat, and nothing on it is a bubble. Its parts:

- **The record** (`Transcript.tsx`, `timeline.ts`): the session as one timeline on a rail. Each row is a moment with a time column, a mark on the rail and its words. The marks: the agent's glyph for Ghost or the agent; a ring for the operator, with a mic inside for spoken and keys for typed; a wrench for the work between two turns; a check (`--ok`) for a change made; an `x` or a clock for a decision settled; a `?` (`--warn` while open) for a question; a raised hand for a cut; a triangle (`--danger`) for an error; pause for hold; a hung-up phone for a session's end. Ghost's words are `--text-1` at 16/24, the operator's `--text-2` at the same size: the eye lands on the answer. Time is shown where a conversation has it: the clock time on the first row of a session and after a pause, “3 min later” in the gutter with the rail going dotted across a pause of two minutes or more, “Session ended · 4 min” after a stored session, and any row's time on hover or focus. Under 620px of record the gutter goes and the rail stays.
- **The operator's words** appear once their turn closes, as the words the model was given (the `heard` event, ADR 0058), never as pieces while they talk (#73). A reload mid-turn replaces the pieces it loaded the same way.
- **Work** is one row per run of calls between two turns: “Used GitHub · 2 calls · 1.4 s”, shimmering “Using GitHub” while a call runs, opened (a real `button`, `aria-expanded`) to each call with its app, tool, the tool's name in mono, and its time. A handover from the fast model (ADR 0050) is a line inside it. Each call is a disclosure of its own: opened, it fetches what came back (`GET /calls/{id}`, ADR 0058) and shows it in a `--bg-sunken` well in mono, at most 2,000 characters with “N more characters not shown”, “What came back isn’t kept any more” once the daemon has let it go; a change shows the audit's “Changed · …” line first. The rows are kept beside the transcript (`GET /activity`), so history and a reload show them.
- **The reply being said** shows how far the voice has got: said words `--text-1`, the clause the voice is on now `--text-1` underlined 2px in `--phase-speaking` (the daemon's `saying` stamps, ADR 0058), the rest `--text-3`. Without stamps (the cloud voice) it moves word by word on the estimate (`@ghost/ui` `said.ts`). A cut leaves a 2px `--warn` bar where it came and the rest dim. Screen readers get each turn once, whole: the split is `aria-hidden`.
- **Questions** (ADR 0051) sit in the record where they were asked: “Accounting asks: …” in the asker's words, the choices as `secondary` buttons that answer there, or “Answer by voice, or on What needs you” when there are none. Once settled, the row says how it was answered.
- **The stage** (`Stage.tsx`) sits on the composer in a live session and says what is happening now. Its sign is **the presence** (`Presence.tsx`): Wisp in the agent's hue on a halo of its tile color. While someone speaks the strip opens into a band (64px presence, the title at `--text-xl` over its hint, a 7% tint of the phase color): Ghost speaking (Wisp's mouth and lift follow Ghost's own voice level through `Mascot`'s `level`, the halo and an outer ring swell with it through `--lvl`, written per animation frame, and the `ribbon` waveform runs across), the operator speaking (“Listening to you · Ghost answers when you finish”, Wisp leaning in wide-eyed, three `--phase-listening` rings flowing in toward it at a steady pace, the same at any volume, never words; from the turn opening or held pieces, never the microphone's level). At rest it is one 32px line: working (the thinking pose and an arc turning round the halo, “Using GitHub” from the live calls), listening, on hold (Wisp dozing, “Say “Ghost” to pick up again”), saying goodbye, on the phone. With the mic off (ADR 0057) the listening line reads “Mic off · Type below. Ghost can’t hear you.” with the halo struck in `--danger` and a secondary **Listen again**, and the same strip sits over the composer outside a session too; the composer's voice control is then the struck mic in `--danger` that turns listening on, and the start state says “Ghost isn’t listening”. In a session the composer drops its presence: the stage carries it.
- **Room view** is the same moment from across a room: the presence at 120px (168px while the operator speaks) over the reply at `--text-5xl` with said, the clause being said underlined, and unsaid, the waveform at 72px across the page, the operator's last words while Ghost works, “Waiting for your okay” and the change's words when one waits (the dock's Confirm stays where it is). It comes on by itself after 20 seconds with nobody touching the computer in a spoken session, goes at the first pointer move, key or scroll, and the stage's button turns it on and off by hand (Escape leaves). It is drawn over the record, which stays in the page for screen readers (`aria-hidden` on the room).
- **What came back, in words** (`result.ts`, `shapeOf`): an opened call's preview, when it parses, reads as a list of items by their titles (“12 items of 40”, the first eight with a mono meta of number, state, date, then “and 4 more”), one thing's title and fields (keys in words, “Updated at”), or a message's words. A preview cut mid-JSON, or a shape it can't say, stays raw. “Show it as it came back” toggles the raw well (`aria-expanded`, `aria-controls`); the same 2,000 characters and redaction as before, every word `data-user-content`.
- **Hear it again**: with no session open, a reply of 200 characters or less has “Say it again” on hover or focus, in its agent's voice (`POST /voices/{voice}/sample`), next to Copy. Never during a session: Ghost's voice would reach the microphone.
- Reduced motion: the ring, the arc and the shimmer stand still, Wisp holds its mood's one pose, the halo stands at a middle size, one inward ring stands at its middle, the band opens without its transition, room view appears without its fade, the waveform draws one still frame. Forced colors: the cut bar is `Highlight`.

## Routing

Hash routes, registered in `src/app/routes.tsx`. Each entry has `id`, `patterns`, `path`, `owner`, `title`, `kind` (`screen`/`prototype`/`foundation`), `chrome` (`app` or `bare`), `needsDaemon`, an optional `nav` item, an optional `area: "settings"` (a page of Settings, with the settings nav beside it), an optional `accept` (narrows a `:param` to some values) and a `React.lazy` component. An address that moved goes in `REDIRECTS` there: the shell shows the new page at once and replaces the hash, so links in notes and docs keep working. Screens receive `{ params }` (e.g. `params.slug`). Navigate with `<Link to="/audit">`, `hrefFor(path)` or `navigate(path)` from `src/app/router`. Only hashes that start with `/` are routes; any other hash (`#main`, `#gal-color`) leaves the route alone, so an in-page anchor can never navigate to a 404. Still, never use `href="#id"` for an in-page jump: use a button that focuses or scrolls (the shell’s “Skip to content” is a button for this reason).

Prototype routes and the gallery are compiled only in development (`import.meta.env.DEV`) and appear in the rail’s design menu only when the mock layer is active. The shell puts a strip over every prototype route: with the mock, “Prototype · Mock data only. Not connected to Ghost.”; against the real daemon, in warn tone, “Prototype · Connected to your Ghost. Saves here are real.” A prototype never adds its own badge for this.

### Adding a route

1. Create `src/screens/<owner>/index.tsx` (or `src/prototypes/<owner>/`) with a default export `function X({ params }: RouteProps)`, and `<owner>.css` imported from it.
2. Ask the foundation owner to add one entry to `ROUTES` in `src/app/routes.tsx` (and, for a prototype with its own data, one line in `src/design/mock/fixtures/index.ts`).
3. Add the route to your screenshots in every relevant scenario, both themes.

| `busy` | Months of use: 13 agents, 200 audit rows, several apps (two GitHubs, a calendar, Mobbin, one that is connecting and one whose command isn’t installed), eight skills, three of them the operator’s own, four outputs, a watch that can’t read (its app isn’t connected), a paused watch Ghost made, a question asked from a scheduled run, a webhook that is off (its secret isn’t set), and two problems the daemon reports in `watches.json` and `hooks.json`; four schedules, one whose last run failed and one paused, and a schedule that can’t run because its agent is retired. |
| `notlistening` | The operator turned listening off (ADR 0057): the status card reads “Not listening · Mic off” with the struck mic in `--danger` on the danger tint, the switch by the brand is red, Settings › Sound says so, a Call is refused and typing still opens a session. `&listening=off` or `&listening=<minutes>` turns it off in any scenario, for a time (“Mic off until 3:30 PM”). |

URL options on any scenario: `&posture=room` opens in the room (held) and `&posture=desk` never leaves the desk, so every scenario is also a room scenario (`?mock=busy&posture=room`, `notlistening`, `disconnected`, `session`, `firstrun`); `&latency=0` answers instantly (default 140ms, to show loading states); `&connect=600` holds the event stream’s first open for 600ms (the Connecting state; past 900ms the shell shows Offline until it connects); `&drop=2000` drops the daemon 2 seconds after load (stream closes, requests fail); `&back=6000` brings it back 6 seconds after the drop. `&phone=off|unpaired|paired` sets the phone listener (ADR 0016): off, on with no phone, or a phone paired on the home network only (the tunnel guide shows); `&phone=tunnel` adds a tunnel address the phone last came in through, and `&phone=tunnel-down` one whose interface isn't up yet (ADR 0020); `&phone=pairs` has the phone pair 5 seconds after a code is issued, and `&phone=expires` makes codes last 8 seconds. `&settings=pairing` opens Pair a phone on load, on the Phone page. `&floating=on|off|refused` sets the floating room's switch in the main window (ADR 0059: on and up, off, or a desktop that can't float); `&capture=yes` says the screen is being shared. On `floating.html` any scenario plays in the floating room, with `&main=active` (the main window is in use, so nothing floats), `&capture=yes` (nothing drawn), `&covered=1` (a full-screen app has the only monitor), `&side=left|right` (one monitor, the stage beside the work) and `&still=1` (reduced motion). `&build=dev|dirty|start|checkout|deploy|release|behind` sets what the daemon says it is (docs/releasing.md): a checkout at this window’s version and commit that `make dev` started (default), the same with uncommitted changes, one `make start` started, one started some other way, a `make deploy` build or the package at this version but another commit (the builds differ), or last month's deploy (the versions differ), so the sidebar and Settings › General show that the window and Ghost differ; the restart bar says `make reload` for `dev` and `dirty`, `make restart` for `start`, “Restart Ghost the way you started it” for `checkout`, and `systemctl --user restart ghostd` for the others. `&vault=locked|import|broken` sets Ghost’s vault (ADR 0036): the keyring is locked (Unlock opens it after a moment), plaintext files wait to be imported in any scenario, or the key in the keyring doesn’t open the vault. `&catalog=slow|problem|empty` sets the app catalog’s copy (ADR 0034): the first copy takes 4 seconds (first run does this without asking), the copy is three days old and its refresh failed, or no copy has arrived yet and none does for 8 seconds. `&skillsearch=down` has skills.sh not answer, so Find skills on Settings › Skills says so (#35); in `busy`, Design review was installed from GitHub and its source has moved on (Update…), and Expense report was installed from GitHub and is current. In `pending` the fixture’s change is held open for design work; changes you make Ghost propose while using the mock expire after 60 seconds, as the real daemon’s do.

The mock is an in-memory ghostd (`src/design/mock/daemon.ts`) that implements every client method and the event stream, so interactions work: typing a message runs listening, thinking, speaking; "close" proposes a confirm-level change; Confirm and Cancel settle it and write the audit log in the gate’s words (the summary turns past tense, “closed the issue”, and the steps read as the gate’s `describe()` does: “comment: …”, then “closed the issue”); "transfer me to legal" switches agents, with the old agent speaking “Transferring you to Legal.” (or “Back to Ghost.”) as `ghost_voice::conversation` does; conversation edits, notes, reset, delete and compact all update state and emit `conversation` events; policy and settings saves persist for the page’s life. Skills (ADR 0023): add and remove change the in-memory list and write an audit row at `quiet`; the mock has no file system, so a dropped or typed path becomes a skill named after its last folder, and it refuses with the daemon’s own 409 sentences when the path is a file, a home or downloads folder, already inside `~/.config/ghost/skills`, or a name already installed (where the screen offers Replace). A skill of the operator’s can’t be removed (409), as on the real daemon. Ghost’s folder (ADR 0035): `GET /rules`, `GET /outputs` and `GET /watches` answer from the fixtures; the schedules (ADR 0047, `mock/schedules.ts`) can be added, paused, resumed, removed and run now, with the daemon’s own 422 sentences, and a run started in the mock finishes after a moment and puts its answer on What needs you; `POST /rules` goes through a fake gate the way the daemon’s `apply_internal` does: a `block` rule naming `rules.add` refuses it with 409 and the gate’s sentence, anything else appends the text verbatim (a `# Ghost` heading when the file is empty), writes an audit row at `quiet` and answers the outcome. Proposals and audit rows carry the agent of the live session.

### Fixtures

Each owner's data lives in `src/design/mock/fixtures/<owner>.ts` as a default export `(scenario) => data`. Read the scenario's flags (`daemon`, `phase`, `session`, `pending`, `configured`, `data`) rather than its name, so new scenarios work everywhere. Use `ago(minutes)` for timestamps so relative times stay fresh, and `seeded(n)` for stable generated data. Paths are written from `~` (`~/.config/ghost/policy.toml`, `~/.local/share/ghost/conversations/<slug>`), never a real home directory. Keep data specific and believable: real-looking issues in `ghost-mock/app` and `ghost-mock/infra`, named teammates, the operator's plain voice.

Prototypes have no API behind them; read their fixture with `useFixture<T>("<owner>")`, importing the type only (`import type { ReviewFixture } from "../../design/mock/fixtures/review"`). `useFixture` returns null outside mock mode, so handle that.

## Screenshots

```
node .scratch/design/tools/shot.mjs "<url>" .scratch/design/shots/<owner>/<name>.png \
  [--theme dark|light] [--size 1440x900] [--full] [--click "Exact text"]... [--click-label "Accessible name"]... \
  [--hover "Exact text"] [--wait ms] [--mobile] [--scroll px] [--tab n]
```

`--click-label` clicks by accessible name (an IconButton’s label: `--click-label "More for Accounting"`); `--hover` rests the pointer on an element before the shot (tooltips, hover-only row actions). For a sequence (type, press Enter, change the hash, scroll to a section), `act.mjs` takes the same first two arguments and an ordered list of `--click`, `--type <selector> <text>`, `--press <key>`, `--hash /path`, `--scroll-to <selector>`, `--wait ms`, `--eval <js>`.

- The page panel scrolls, not the window. `--full` sets `<html data-capture="full">`, which lets the panel grow to its content so the whole page is captured; never set that attribute in the app.
- `--scroll 600` scrolls the panel before the shot (check sticky headers, the dock, the fade). `--tab 3` presses Tab three times (check focus).
- Shoot every screen in both themes at 1440x900 and at 1280x800, in every scenario that changes it. Use `--wait 1300` or more for `disconnected` (the shell waits about 900ms before deciding the daemon is down).
- The script prints page errors and console errors. Any output there is a bug.
- `--mobile` renders 390x844 at 3x for `#/mobile`.

## Review checklist

- One focal point; at most one primary button and one tinted card in view.
- Scrolled at least one screen (`--scroll`): the panel edge stays put, sticky things don’t let content peek, the dock fades.
- Toolkits: the designer is a real GUI, never a TOML field. A level select offers the policy’s level and anything more cautious (deny < confirm < announce < quiet), with the ceiling named under it; a saved level the policy no longer allows stays visible with the daemon’s problem under it. Problems come from the daemon, shown once in a warn Notice and again on the control they are about.
- Only tokens; no raw colors, sizes, shadows or durations.
- Sentence case, plain labels, env names only as `detail`.
- One `h1` per screen. Development builds count them in the page panel once it settles and log a console error otherwise.
- Keyboard: from a fresh load the first Tab reaches “Skip to content” and Enter on it lands in the page; everything reachable with Tab, once (no duplicate tab stops), visible focus, Escape closes overlays, Enter submits forms, Enter and Space open menus.
- Loading, empty, error and offline states designed and screenshotted.
- Dark and light both checked; text contrast at least AA, body text AAA.
- Nothing scrolls horizontally at 1280x800.
- No page errors in the screenshot output.
- Typecheck (`pnpm -s typecheck` at the repo root) and production build pass.
